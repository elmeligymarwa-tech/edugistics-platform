DATABASE RULES
  Unique composite index on (courseId, teacherId). Duplicate prevention must
    hold at database level, not only in application code.
  Index courseId, teacherId, registeredAt, schoolId, status.
  Never hard delete a registration. Use status CANCELLED.
  Never hard delete a course. Use archivedAt.
  Instantiate PrismaClient as a module level singleton to avoid exhausting
    connections in serverless.

NORMALISATION
  Email: lowercase and trim, keep the original.
  Phone: strip spaces, brackets, hyphens, keep a leading plus, keep the
    original.
  School nameKey: lowercase, trim, collapse spaces, strip punctuation, strip
    trailing words school, schools, international, academy. Lookup key only.
    Never overwrite what the teacher typed.
  Subject and grade: lowercase and trim into a normalised column, keep the
    original, no synonym mapping.

School matching: exact nameKey match against School or SchoolAlias, else
create a new School. No fuzzy matching. Merging is a manual admin action.

ADMIN LOGIN at /training/admin/login
  Verify the submitted password against ADMIN_PASSWORD_HASH using argon2
    verify. Never compare plain strings. Never log the password.
  On success set a signed httpOnly, secure, sameSite lax cookie using
    ADMIN_SESSION_SECRET. Expiry 8 hours.
  Add a logout route.
  Rate limit to 5 attempts per 15 minutes per IP.
  Check the session server side inside every admin route and every admin
    action. Hiding a link is not protection.
  Add a script registered as admin:hash that prompts for a password, prints
    the argon2 hash and nothing else, and never writes it to a file.

COURSE MANAGEMENT
  Course list: name, date, status, registrations, waitlist count, capacity,
    active toggle
  Create and edit forms using react-hook-form with zod resolvers and the
    existing shadcn form components
  Archive action with confirmation dialog

  Capacity controls:
    Maximum Capacity, optional, blank means unlimited
    Enable Waitlist switch, disabled while capacity is blank
    Waitlist Capacity, shown only when the switch is on
    Helper text: waitlist off closes registration when full, waitlist on
      keeps collecting names in order

  Server side validation with zod:
    Cannot activate without name, date, start time and delivery method
    registrationClosesAt after registrationOpensAt
    Location required when delivery is not ONLINE
    waitlistEnabled cannot be true when maxCapacity is null

==================================================

PUBLIC PAGE at /training

Mobile first. Under two minutes to complete. Professional, minimal,

  Fee above zero shows the amount plus: Payment is not collected through
    this form. Payment instructions will be sent separately.
  Full with waitlist on: This course is full. Join the waiting list.
  Full with waitlist off: shown as Full, not selectable

Fields
  Course, Full Name, Email, Phone, Current School, Subject Taught, Grade or
    Year Group all required
  Address optional
  Marketing consent checkbox, unticked by default, never pre-ticked
  Privacy notice with a link above the submit button
  Hidden honeypot field

SERVER ACTION LOGIC
1. Validate every field server side with zod.
2. Reject if the honeypot is filled.
3. Rate limit by IP, 5 submissions per hour.
4. Normalise email, phone and school name.
5. Resolve or create the school.
6. Find the teacher by emailNormalised. Update and reuse if found, create if
   not. Never duplicate a teacher for a repeat email.
7. Reject a duplicate non-cancelled registration for the same course with:
   This email address is already registered for this course.
8. Apply capacity inside a transaction with a row lock on the course so two
   simultaneous submissions cannot both take the last seat:
     maxCapacity null: CONFIRMED
     confirmed count below maxCapacity: CONFIRMED
     full and waitlist off: reject with This course is now full.
     full and waitlist on, waitlist also full: reject with This course and
       its waiting list are both full.
     full and waitlist on: WAITLISTED, position = waitlist count plus 1
9. Reference EDU-YYYY-XXXXXX using the Cairo year plus six random uppercase
   alphanumeric characters. Retry on collision.
10. Write the registration with all snapshot fields populated.
11. Send the email after the transaction commits.
12. Email failure must not lose the registration. Record FAILED and the
    error.

PHASE 4 - ANALYTICS
==================================================

CENTRALISED CALCULATION LAYER
One analytics module. Every metric has exactly one implementation. No
component recalculates anything. No formula appears twice.

One filter type applied by one function:
  AnalyticsFilters { dateFrom, dateTo, courseIds, categories, schoolIds,
    subjects, grades, teacherType, status, marketingConsent }

Every query takes the same filter object. Filtered and unfiltered values
never mix inside one view.

DEFINITIONS
  Total Registrations = count where status CONFIRMED
  Waitlisted = count where status WAITLISTED
  Cancelled excluded from every metric unless a view reports cancellations
  Unique Teachers = distinct teacherId in the confirmed set
  Unique Schools = distinct schoolId in the confirmed set
  Repeat Teachers = teachers with more than one confirmed registration
  Average Registrations per Course = confirmed registrations divided by
    courses with at least one confirmed registration
  Potential Registration Value = sum of courseFeeSnapshot across confirmed
    registrations only, waitlisted excluded
  Course Utilisation = confirmed divided by maxCapacity times 100, null when
    maxCapacity is null
  New Teacher 1 confirmed, Engaged 2, Highly Engaged 3 or more

TIMEZONE
  All grouping and all date filters use Africa/Cairo via date-fns-tz.
  Convert before grouping. Never group in UTC. Write a test proving a
  registration at 23:30 Cairo falls on the correct local day.

AGGREGATION
  Aggregate in SQL through Prisma groupBy or raw queries. Never pull rows
  into memory to count them.

DASHBOARD at /training/admin
  Header, global filter bar, date presets Today, Last 7 Days, Last 30 Days,
  This Month, Last Month, This Year, All Time, Custom Range
  KPI row: Registrations, Unique Teachers, Unique Schools, Active Courses,
    Repeat Teachers, Potential Value
  Registration trend line chart with day, week and month toggle, recharts
  Course performance bar chart plus a table with confirmed, waitlisted,
    capacity, remaining seats and utilisation
  Subject distribution and grade distribution charts built from submitted
    data only, never hardcoded
  Top schools table with Top 10, Top 20 and All toggle
  New versus returning teachers

  Everything responds to the filters. Add no charts beyond this list.

COMMERCIAL SECTION
  Free registrations, paid registrations, potential value by course, by
  month. Label everything Potential Registration Value. Never use the word
  revenue. Never imply payment was received.
